## 2. ข้อตกลงทางเทคนิคที่ต้องรักษา

- ใช้ `createScene` จาก `src/scripts/_shared/scene-runtime.ts` กับ `createRng`, `createNoise2D`, `fbm2D`
- แยกเป็นไฟล์ `*-core.ts` (คำนวณล้วน ไม่แตะ DOM และมีเทสต์) กับ `*-scene.ts` (วาดบน canvas)
- สัญญาการผูกธีมใน `src/pages/index.astro` ต้องคงเดิม: `__bind<Key>`, `__<key>Cleanup`, `__<key>Initialized`
- คงค่า theme และ key เดิมเพื่อไม่ให้ค่าที่ผู้ใช้เลือกไว้เสีย:
  - `constellation` / `DynamicCityBg`
  - `pages-stars` / `PagesStarsBg`
- รูปแบบ component ใช้ตาม `MothlightBackground.astro`: selector `avoid`, `avoidSoft`, `pointerBlock`, `start()` และ `destroy()`
- วาดของหนักล่วงหน้าลง offscreen canvas ตอน resize ใช้ seed คงที่ และห้าม reseed เมื่อขนาดจอเปลี่ยน
- `dprCap` 1.5, ใช้ pool แทนการสร้างวัตถุใหม่ทุกเฟรม, หยุดเมื่อซ่อนแท็บ
- ลดการเคลื่อนไหว: ใช้ `reducedMotionFrame` วาดภาพนิ่งที่จัดองค์ประกอบสวยงาม
- มือถือแนวตั้ง แนวนอน และจอกว้าง ต้องจัดองค์ประกอบใหม่ ไม่ใช่แค่ย่อภาพ
- แสงต้องไม่กะพริบเร็วเกิน 3 ครั้งต่อวินาที

งบประสิทธิภาพ: เวลาวาดเฉลี่ยไม่เกิน 6 ms ต่อเฟรมที่ 1440x900 บนเครื่องทดสอบ และชิ้นโค้ดของแต่ละฉากไม่เกิน 30 KB หลัง gzip

### ชั้นภาพจากหลังไปหน้า

| ชั้น | รายละเอียด | ประเภท |
|---|---|---|

| สมุด | ปกทองลวดลายเรขาคณิต แผ่นกระดาษซ้อนเป็นชั้น ริบบิ้นคั่นหน้า | ผสม |

### การเคลื่อนไหวหลัก

1. **สมุดหายใจ:** ลวดลายบนปกและแกนแสงสว่างขึ้นลงช้า ๆ
2. **พลิกหน้า:** ทุก 6 ถึง 11 วินาที หน้าหนึ่งพลิกจริงด้วยแถบกระดาษหลายช่องที่โค้งตามเส้น Bezier และมีเงาไล่ตามความโค้ง
3. **กระดาษหลุดลอย:** ดีดขึ้นจากสันสมุด แล้วเคลื่อนตามเส้นลมหลักแบบ Catmull-Rom ผสมสนามแรงจาก noise
4. **กระดาษเป็นสามมิติ:** หมุนสามแกน ย่อด้านตามมุม โค้งตามแกนยาว มีตัวอักษรรูนและหน้าหลังคนละเฉด
5. **สลายตัว:** ไหม้จากขอบด้วยขอบเรืองแสงสีส้ม แตกเป็นละอองตามเส้นลม
6. **จุดเด่นของธีม:** ละอองที่ขึ้นไปถึงกลุ่มดาวจะรวมเป็นดาวดวงใหม่ที่อยู่นานประมาณ 40 วินาทีแล้วจาง ทำให้เห็นหน้าหนังสือกลายเป็นดาวจริง

### การโต้ตอบ

- ขยับเมาส์: เกิดแรงลมตามทิศ หน้ากระดาษและละอองเบี่ยง
- ชนหน้ากระดาษ: หน้าไม่แตกทันที แต่พลิกตัวหนีและสลายเร็วขึ้น
- แตะสมุด: สมุดเปิดพรึบ ปล่อยกระดาษ 4 ถึง 6 หน้าพร้อมคลื่นแสง
- แตะท้องฟ้า: ดาวรอบจุดแตะสว่างวาบและกลุ่มดาวที่ใกล้สุดลากเส้นทันที
- บริเวณข้อความและการ์ดอยู่ใน `pointerBlock` ไม่รับการโต้ตอบ

### องค์ประกอบตามจอ

| จอ | สมุด | ทิศเส้นลม |
|---|---|---|
| จอกว้าง | ล่างซ้าย พ้นการ์ดและชื่อเว็บ | ล่างซ้ายขึ้นขวาบน |
| มือถือแนวตั้ง | ล่างกลางค่อนซ้าย ขนาดเล็กลง | ขึ้นเป็นรูปตัว S |
| มือถือแนวนอน | มุมล่างซ้าย เล็กพิเศษ | แนวราบ |

### เทสต์ของ core

- `computeBookLayout`: สมุดอยู่ในจอครบทุกขนาดที่ Mothlight ทดสอบ และไม่ทับพื้นที่ `avoid`
- `windPath`: เส้นต่อเนื่อง จบในจอ และกลับทิศตามองค์ประกอบ
- `pageFlipCurve`: ปลายทั้งสองติดสัน ความโค้งสมมาตรตรงกลางการพลิก
- `pageLifecycle`: ความทึบอยู่ในช่วง 0 ถึง 1 และจบที่สลายตัวเสมอ
- จำนวนอนุภาคไม่เกินเพดานเมื่อแตะรัวติดกัน

| ชั้น | รายละเอียด | ประเภท |
|---|---|---|

| ดาวตก | เก็บพฤติกรรมเดิม ทุก 5 ถึง 9 วินาที | สด |

### วิธีวาดสายแสง

1. ทุกเฟรมคำนวณแนวกลาง `x(y, t)` จากคลื่นไซน์หลายความถี่ผสม noise
2. คำนวณ "มุมบิด" ตามความสูง ทำให้ความกว้างแคบลงตรงจุดพลิกและสว่างขึ้นตรงขอบพับ เหมือนริบบิ้นจริง
3. วาดเป็นแถบแนวนอนบาง ๆ ลง offscreen ขนาด 1/3 ของจอ ด้วยการไล่สีจากขอบทองอ่อน กลางอำพัน และเงาแดงเข้ม
4. ขยายกลับด้วย `lighter` ซ้อนกับรอบเบลอ เพื่อให้แสงฟุ้งโดยไม่ใช้ `filter` ราคาแพงต่อเฟรม
5. มีจังหวะ "ชีพจร" เป็นระยะ แสงเส้นหนึ่งไหลจากบนลงล่างแล้วกระจายที่พื้น

### การโต้ตอบ

- เมาส์เข้าใกล้: สายแสงโค้งเข้าหาด้วยแรงสปริง และโหนดดาวถูกผลักออก
- แตะ: คลื่นวิ่งไปตามสายทั้งขึ้นและลง ดาวรอบจุดแตะวาบ และเกิดระลอกบนเงาสะท้อน
- มือถือ: ใช้ `TOUCH_LINGER` แบบเดียวกับ Mothlight

### การแก้ประสิทธิภาพจากของเดิม

ของเดิมตรวจระยะโหนดทุกคู่ทุกเฟรม ฉากใหม่ใช้ตารางแบ่งช่องเพื่อลดการตรวจ

### เทสต์ของ core

- สายแสงอยู่ในจอทุกความสูงและเลี่ยงกลางการ์ดหลักบนจอกว้าง
- ความกว้างไม่ติดลบเมื่อบิดเต็มที่
- `springBend` กลับสู่ศูนย์เมื่อไม่มี pointer
- ตารางโหนดให้ผลคู่เท่ากับการตรวจทุกคู่
- ระลอกแตะจบและคืนหน่วยความจำให้ pool

- เก็บ `id`, avatar และความคืบหน้าเดิมทั้งหมด เพราะข้อมูลอ้างอิงด้วย `id`
- `localStorage` ใช้งานไม่ได้: ข้ามอย่างเงียบ ไม่ทำให้หน้าเสีย

### กติกาเนื้อหาชื่อ

- ภาษาไทย ใช้มุขสไตล์ต่างชาติ: เกม, ออฟฟิศ, โปรแกรมเมอร์, ไซไฟ, แฟนตาซี, ฉากซ้ำซากในหนังฝรั่ง
- ห้ามคำหยาบ เรื่องขับถ่าย เรื่องเพศ การล้อเรื่องเชื้อชาติ เพศ ศาสนา ความพิการ หรือคนจริง
- หลีกเลี่ยงอาหารและวัฒนธรรมไทยเป็นแกนของมุข
- ความยาวไม่เกิน 24 ตัวอักษรที่มองเห็น และต้องไม่ล้นกรอบโปรไฟล์
- ชื่อตัวอย่างของผู้เขียน "เกาลัดพลังคลื่นเต่า" ต้องอยู่ในรายการ

### ตัวอย่างโทน

เกม: NPC ผู้ไม่ยอมหลบทาง, บอสด่านแรกเลเวล 99, คัตซีนที่กดข้ามไม่ได้, นักดาบผู้ลืมเซฟ, ฮีลเลอร์สายตีหัว, เควสต์ข้างทางตลอดชีพ

ออฟฟิศ: คุณประชุมที่ควรเป็นอีเมล, ผู้จัดการฝ่ายรับทราบครับ, ไฟล์ Final จริงจริงV9, ฝ่ายบุคคลแห่งจักรวาล, มนุษย์ตอบช้าเพราะแบตหมด

โปรแกรมเมอร์: 404 ไม่พบชื่อนี้, บั๊กที่กลายเป็นฟีเจอร์, คนกด Ctrl+Z ชีวิต, เซมิโคลอนหายสาบสูญ, ลองปิดแล้วเปิดใหม่หรือยัง

ไซไฟและแฟนตาซี: มนุษย์ต่างดาวลงจอดผิดดาว, หุ่นยนต์ขอลาพักร้อน, มังกรเฝ้าสมบัติกะดึก, พ่อมดลืมรหัสผ่าน, ไวกิ้งแพ้น้ำ, แวมไพร์สายตื่นเช้า

ฉากซ้ำในหนัง: พ่อบ้านทำแน่นอน, ผู้ร้ายขอพูดอีกนิด, ตัวประกอบเสื้อแดง, นักสืบลืมแว่นขยาย, ผีที่กลัวความมืด, ซอมบี้ขี้เกรงใจ, นินจาที่ทุกคนเห็น, อัศวินแพ้ฝุ่น

## 7. เกณฑ์ตรวจรับ

1. รันเทสต์ `src/scripts/hub/*.test.ts`, `hub-ui-contract`, `hub-portal-contract`, `reading-experience-contract`
   - เทสต์ภาพอำลาของ Tsukinomi ใน `reading-experience-contract` ไม่ผ่านอยู่ก่อนแล้ว ต้องรายงาน ไม่ใช่ซ่อน
2. `astro check` ไม่เพิ่มข้อผิดพลาดใหม่ และ `pnpm build` สำเร็จ
3. เปิดดูจริงทั้ง 2 ธีมที่ 1440x900, 1280x800, 2560x1440, 390x844, 844x390, 320x568
4. ทดสอบเมาส์ แตะ สลับธีมทั้ง 4 แบบ ไปหน้าอื่นแล้วกลับ และไม่มีลูปค้างหลัง `astro:before-swap`

6. วัดเวลาวาดด้วย `src/scripts/tsukinomi/scene-measure.ts` โดยใช้เป้าหมาย `url:/` และบันทึกตัวเลขพร้อมขนาด gzip
7. ค้น `dist` ไม่พบไฟล์ภาพเก่า 2 ไฟล์ และไม่พบชื่อหยาบชุดเดิม
8. ไม่มี error ใน console และข้อความกับปุ่มบนฮับยังอ่านได้ชัดเหนือฉาก
9. ส่งภาพหน้าจอจริงให้ผู้เขียน รวมภาพมือถือ

## 8. การ commit และ push

- ผู้เขียนต้องการ push รวดเดียวหลังงานเสร็จ
- ก่อน stage ให้ตรวจ `git status --short` และ stage แบบระบุ path เท่านั้น ห้าม `git add -A` หรือ `git add .`
- ห้ามรวม `src/plan/the-sea-that-hung-above-the-world/**`
- ถ้า session Kusabi ทำงานในโฟลเดอร์เดียวกัน: ฝั่งฮับเป็นผู้ push ครั้งสุดท้ายหลังตรวจ build รวม เว้นแต่ผู้เขียนสั่งเป็นอย่างอื่น
- ใช้โฟลเดอร์ build แยกกับ session อื่น: `pnpm exec astro build --outDir .qa/dist-hub`
- หลัง push ตรวจผล workflow `deploy-pages` และเปิดหน้าเว็บจริง

## 9. ความเสี่ยง

| ความเสี่ยง | ผลกระทบ | วิธีรับมือ |
|---|---|---|
| ฉากสวยแต่หนักบนมือถือ | เว็บกระตุก | จำกัดอนุภาคตามขนาดจอ, วาดล่วงหน้า, วัดจริงทุกขั้น |
| ฉากแย่งสายตาจากการ์ดนิยาย | อ่านยาก | ใช้ `avoid` และลดความสว่างหลังการ์ด |
| แถบสีบนไล่เฉดเข้ม | ดูถูกกว่าภาพเดิม | เติม dithering ในชั้นวาดล่วงหน้า |
| เขียนลวดลายมือไม่ถึงระดับภาพเดิม | ไม่ดีกว่าเดิม | ตรวจจากภาพหน้าจอทุกขั้น ก่อนลบไฟล์ภาพเก่า |

| คำเก่ายังอยู่ในประวัติ Git | ยังค้นเจอย้อนหลัง | รายงานให้ทราบ ไม่เขียนประวัติใหม่ |
